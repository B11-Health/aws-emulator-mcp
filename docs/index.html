FOUR DEVELOPER GOALS · STATIC PREVIEW · NO TELEMETRY

What are you trying to do?

No AWS vocabulary needed to start. Choose a goal to see a pinned, separately verified command path, what it checks, what it does not prove, and one next step. Run all steps from the same parent directory. Copy one step at a time in Bash or PowerShell. Never paste a Clone, Verify, and Run sequence together: Git may refuse an existing directory. The Run buttons check the exact pinned commit, safe Git index flags, and all tracked bytes themselves before launching repository code. Cloning disables Windows CRLF conversion so verification compares exact bytes. Copying text never executes it. These paths are in this draft source checkout and are not yet a published update to the public Demo Studio.

06 / BEFORE YOU TRUST A GREEN TEST

Four questions worth asking.

Short answers grounded in local tests and documented boundaries. The emulator is evolving; always evaluate the exact release and operations you need.

Does this replace AWS or validate IAM permissions?

No. Our emulated S3, DynamoDB and SQS workflows verify specific behavior; they do not establish production AWS parity or enforce IAM policies like real AWS. A CloudFormation CREATE_COMPLETE result is not enough—read back the resource using its service API and preserve a small real-AWS test suite for permission-sensitive paths.

An independent 18-service report documented gaps in an earlier emulator version (1.0.322). That version-specific report is useful for choosing tests, not a score for the current release.

Can Claude Code, Copilot, or other coding agents use it?

Yes, with the appropriate local integration. AWS Emulator itself can be used through its official agent skill or the native AWS SDK/CLI; you do not need this adapter for that. Our optional MCP adapter exposes bounded local stdio tools. The guided connection setup shows current VS Code Copilot configuration and an unsigned Claude Desktop extension preview.

Our CI verifies official Python and TypeScript MCP SDK clients, but a complete independent Claude Desktop installation and real tool call has not yet been verified. A configuration file alone is not a working client session.

Will this run on a normal laptop?

The first, offline step is lightweight: Node.js 20+ and Git, no Docker or AWS account. Emulated AWS API calls additionally need a local Docker Engine or Docker Desktop running Linux containers, a substantial signed upstream package download and image build, and enough disk headroom. We do not claim a universal laptop RAM or startup-time minimum.

On newer repository source, read-only preflight --json reports host working-volume space and cached image freshness; on a host-visible Linux Docker data root it may also report that volume. These are advisories, not Docker Desktop VM capacity measurements, and are not included in the immutable beta.15 tag. Start with the zero-Docker command.

Why use an MCP adapter instead of the native AWS SDK?

Use the native SDK/CLI when it is simpler. The MCP layer adds value when a coding assistant needs a narrow, auditable tool interface for reproducing an order-processing bug, comparing two trusted local handlers, inspecting cleanup assertions, or reviewing an infrastructure blueprint. The adapter does not deploy CloudFormation to AWS or make unsupported emulator services work.

See the honest comparison, then try one concrete example. We welcome a sanitized first-run report, especially if the native tools serve you better.
