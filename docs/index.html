NATIVE COPILOT HARNESS · LOCAL STDIO

Connect VS Code Copilot

From your beta.15 checkout, print a server configuration that contains your own Node path. The CLI does not edit any editor settings.

node bin/aws-emulator-mcp.mjs config copilot
  1. In VS Code, choose a Copilot session and open Chat: Open Customizations → MCP Servers → Add Server.
  2. Choose a local Command (stdio) server and use the generated mcpServers entry. Global config: ~/.copilot/mcp-config.json; workspace option: root .mcp.json.
  3. Start local Docker (Linux containers), then ask your agent to call emulator_doctor and show actual results.
The legacy config vscode output uses a different, deprecated editor-managed servers format. Printing configuration is not a successful MCP tool call.

LOCAL DESKTOP EXTENSION · UNSIGNED DEVELOPER PREVIEW

Try the Claude Desktop MCP Bundle

The .mcpb contains our Node launcher and source files, not the emulator image. This is a developer preview, not a signed or directory-listed extension.

  1. Open the Desktop MCPB workflow runs and choose the latest successful master build.
  2. Download the macOS or Windows UNSIGNED artifact ZIP; inspect SHA256SUMS.txt and extract the .mcpb package.
  3. In Claude Desktop, open Settings → Desktop app → Manage Extensions → Advanced settings → Install Extension. Review and select the local file.
  4. Start local Docker with Linux containers, then try a real emulator_doctor tool call.
Unsigned packages can execute with your host-user permissions. Review before installing. The packaging was tested on Windows, Linux and macOS; a clean, independent Claude Desktop tool session is not yet verified.

NO AI CLIENT · LOCAL EMULATED AWS APIs

Run a complete test yourself

Prefer the terminal? You can reproduce a duplicate SQS fulfillment event and verify the reviewed correction without connecting an AI assistant.

node bin/aws-emulator-mcp.mjs preflight --json
node bin/aws-emulator-mcp.mjs doctor
node bin/aws-emulator-mcp.mjs app-debug compare --json
  1. Install Docker Engine/Desktop and use a local Linux-container daemon.
  2. Run preflight. A failing prerequisite gives a next step instead of pulling an image unexpectedly.
  3. Run doctor and the sample app comparison. Check its actual assertions and scoped cleanup, not just the exit status.
The first emulator test may download a large signed package. The example uses synthetic application data; it does not validate production IAM, AWS parity or transaction atomicity.
