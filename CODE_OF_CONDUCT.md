# Community Code of Conduct

AWS Emulator MCP is an independent open-source development project. We want
contributors, maintainers, reviewers and first-time testers to feel welcome to
ask questions, report failures and challenge technical claims.

## Expected behavior

- Treat others with respect, especially when disagreeing about design,
  security, performance or whether the adapter is useful at all.
- Prefer reproducible evidence and specific suggestions over personal attacks.
- Credit others for their work, respect their time and avoid demanding
  immediate replies from volunteers.
- Keep review feedback about the code, test results and reasoning rather than
  personal identity or experience level.
- Protect other people's privacy. Sanitize logs and never post tokens, private
  paths, customer data or sensitive identifying details.
- Clearly distinguish independently verified behavior from maintainer-run
  tests, unsupported AWS services or marketing claims.

Harassment, threats, hate speech, stalking, repeated unwanted contact,
doxxing, discriminatory comments, and deliberate disruption of collaboration
are not acceptable in repository issues, pull requests, code reviews or linked
project discussion spaces.

## Scope and enforcement

This policy applies to participation in this repository and to community
interactions clearly representing the project. Maintainers may edit or hide
harmful contributions, request changes, temporarily restrict participation or
block users based on the severity and pattern of behavior. We will aim to
consider the context, avoid publicizing personal details and give actionable
explanations when safe and appropriate.

## Reporting concerns

For ordinary technical disagreement or a non-sensitive moderation concern,
open a repository issue referencing this policy, without revealing private
information. Do **not** place personal abuse evidence, sensitive identities or
private correspondence in public GitHub issues.

For harassment, threats or abuse requiring platform intervention, use GitHub's
**Report abuse** controls or GitHub Support. These reports are handled by
GitHub; we do not claim they create a confidential channel to this project's
maintainers.

For a **software security vulnerability**, do not use a public issue. The
repository has [GitHub private vulnerability reporting](https://github.com/B11-Health/aws-emulator-mcp/security/advisories)
enabled; use its **Report a vulnerability** flow and see [SECURITY.md](SECURITY.md).
This security advisory route is for vulnerabilities, not general interpersonal
complaints.

This policy does not supersede GitHub's Terms of Service or Acceptable Use
Policies. The maintainer currently operates a small project, not a staffed
support organization, so response times and confidentiality outside GitHub's
own reporting features are not guaranteed.
